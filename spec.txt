NO external APIs, scraping, or URL fetching.1. System OverviewThe system is a 4-page interactive sentiment analysis application. Each page represents one stage of the pipeline. Users move through stages sequentially. Navigation to a later page is only enabled when the current stage is complete. Every choice made on Page 3 directly controls what is rendered on Page 4 — nothing irrelevant is shown.Page 1 — Data Input & Initial AnalysisUpload CSV or paste text → auto-detect columns → preview data → show KPI cardsPage 2 — Text Cleaning & ExplorationToggle cleaning steps → live text preview updates → word frequency shift chartPage 3 — Sentiment Engine ConfigurationPick sentiment type → pick method → set granularity (if applicable) → runPage 4 — Results & Insight DashboardConditional results — only outputs relevant to Page 3 selections are shown2. Page 1 — Data Input & Initial Analysis2.1  Input methodsUpload a CSV filePaste raw text manually into a text areaNO external APIs, web scraping, or URL fetching of any kind2.2  Auto column detectionWhen data is loaded, the system should automatically identify which column contains text suitable for sentiment analysis. The detection logic should look for columns containing long string values.If auto-detection succeeds — show a dismissable notice: "Text column detected: [column name]. Continue or change below."If auto-detection fails or is uncertain — show a dropdown letting the user manually select which column to use. This handles unexpected column names from Professor Christina's data.2.3  Output — KPI cardsKPIDescriptionTotal recordsCount of all rows in the loaded datasetAverage word countMean number of words per text entryMissing valuesCount of empty or null rows — flagged in red if above 0Language detectedAuto-detected language of the text (e.g. English)2.4  Data preview tableShow first 10 rows of the dataset. Columns: row number, text content, label column (if present). If dataset has no label column, note that ML methods will not be available on Page 3.3. Page 2 — Text Cleaning & Exploration3.1  Cleaning pipeline (left panel)Each step is a toggle (ON/OFF). All steps are ON by default. Page 3 — Sentiment Engine ConfigurationThis is the most important page. Every selection here controls exactly what appears on Page 4. The Run Analysis button is disabled until Steps 1 and 2 are both complete.4.1  Step 1 — Sentiment type (required)User must select one of three types before anything else. This is a separate selection from the method.TypeDescriptionBinaryTwo output classes only: Positive and NegativeTernaryThree output classes: Positive, Negative, NeutralEmotion-basedEight emotion categories using NRC lexicon: joy, anger, fear, sadness, trust, disgust, anticipation, surprise4.2  Step 2 — Method selection (required)Default behaviour: only ONE method can be selected at a time (radio button style). Methods are grouped into two categories.Lexicon-based methodsMethodDescriptionAFINNScores each word from -5 to +5. Sum of scores = sentiment value. Fast, no training needed.BingWord list classifying words as positive or negative. Simple, binary output.NRCMaps words to 8 emotion categories. Only available when Emotion-based type is selected.Machine Learning modelsMethodDescriptionNaive BayesProbabilistic model trained on 80% of data, tested on 20%. Fast baseline.SVMFinds optimal boundary between classes. Generally highest accuracy on text data.Random ForestEnsemble of decision trees. Robust to noisy or messy data.IMPORTANT — ML methods require labeled data. If the uploaded dataset has no label column (detected on Page 1), ML methods must be greyed out with a tooltip: "ML models require labeled data. Your dataset has no label column."4.3  Neutral Granularity slider (conditional)This slider controls the width of the neutral zone — how aggressively borderline words are pushed into positive or negative classes.Visibility rule — show ONLY when ALL of the following are true:Sentiment type selected is Ternary (not Binary, not Emotion)Method selected is AFINN or Bing (not NRC, not any ML model)Behaviour:Low granularity → wide neutral zone → more text stays neutralHigh granularity → narrow neutral zone → borderline words pushed into positive or negative → neutral count decreasesLabel on slider: "Neutral Granularity"Sub-label below: "Higher = fewer neutral results, more words classified as positive or negative"Slider recalculates label distribution instantly — does NOT re-run the model4.4  Enable Model Comparison toggleDefault: OFF. When turned ON:Single model selector is disabled — user cannot pick one modelAll three ML models run automatically (Naive Bayes, SVM, Random Forest)A note appears below the toggle: "All ML models will run. Best performer shown in results."On Page 4: four KPI cards are shown — Accuracy, F1, Precision, Recall — each displaying the best value achieved across all three models. Under each KPI card, a small label shows which model achieved that best score. Example: Accuracy 87% — SVM. F1 0.85 — SVM. Recall 0.82 — Random Forest.A side-by-side model comparison bar chart also appears on Page 4 showing F1-score for all three models4.5  Configuration summaryA live summary strip at the top of Page 3 (and repeated at the top of Page 4) shows all current selections as pill/chip badges: sentiment type, method, granularity value (if active), compare mode status.4.6  Run buttonDisabled until Step 1 (sentiment type) AND Step 2 (method) are both selectedWhen disabled: show hint text — "Complete Steps 1 and 2 to continue"When enabled: button activates and navigates to Page 45. Page 4 — Results & Insight DashboardAll output on this page is conditional. Only components relevant to the selections made on Page 3 are rendered. Components not relevant to the chosen method or type must not appear at all — not greyed out, not hidden behind a toggle, simply not rendered.5.1  Configuration summary (always shown)Repeat the selection summary from Page 3 at the top: sentiment type, method, granularity value if active, compare mode if on.5.2  Outputs — always shown (all methods)Pie chart — sentiment label distribution (2 slices for Binary, 3 for Ternary, 8 for Emotion)Top 5 positive words — horizontal bar chartTop 5 negative words — horizontal bar chartClassified results table — rows with their predicted label. Include filter functionality (filter by Positive / Negative / Neutral)Download button — export predictions as CSV5.3  AFINN-specific outputScore distribution histogram — bars from -5 to +5 showing how many texts fall at each scoreIf Ternary + Granularity slider was used: show how neutral zone boundary affected label counts5.4  NRC / Emotion-specific outputEmotion radar chart — spider/web chart showing all 8 emotion categoriesEmotion bar chart — same data as bar chart for clarityNOTE: Accuracy, F1, Precision, Recall do NOT apply to lexicon methods. Do not show these for AFINN, Bing, or NRC.5.5  ML-specific output (Naive Bayes, SVM, Random Forest only)These components appear ONLY when an ML model was selected:Performance KPIsMetricDescriptionAccuracyOverall percentage of correctly classified rows on test setPrecisionOf all rows predicted positive, how many actually wereRecallOf all actual positive rows, how many were correctly foundF1-scoreHarmonic mean of precision and recall — main performance indicatorVisualsConfusion matrix styled as a heatmap — rows = actual labels, columns = predicted labels. Green diagonal = correct, red off-diagonal = misclassifiedROC curve with AUC score per class — one curve per sentiment classIf Compare mode is ON: model comparison bar chart — F1-score for all three ML models side by side, with the selected model highlighted5.6  Final insights section (always shown)CRITICAL REQUIREMENT: Insights must be generated strictly from the actual computed results and the selected method. They must not be generic placeholder text. The following must be covered:Dominant sentiment — which class appeared most frequently and by how muchKey positive drivers — top words driving positive classificationKey negative drivers — top words driving negative classificationIf ML selected: model performance interpretation — what the accuracy/F1 score means, which class was hardest to classify and whyIf Ternary + Granularity: how the granularity setting affected neutral countIf Compare mode ON: which model performed best and the reason (contextual)One actionable recommendation based on the data (e.g. product quality issues detected, customer frustration patterns, etc.)6. Suggested R File StructureTo keep the codebase clean and manageable, we recommend splitting the R logic into one file per page. Each file handles only its own stage. This makes debugging easier and keeps each team member's work separate.FileResponsibilitypage1_input.RData loading, column detection, missing value count, language detection, preview table, KPI cardspage2_cleaning.RAll preprocessing functions — lowercase, punctuation, numbers, stopwords, stemming, URL removal. Token count before/after. Word frequency data for chart.page3_config.RSentiment type and method validation logic. Granularity slider calculation — neutral zone boundary logic. Compare mode toggle handling.page4_lexicon.RAFINN scoring, Bing scoring, NRC emotion mapping. Output: scored dataframe, top words, distribution data.page4_ml.RTrain/test split, Naive Bayes, SVM, Random Forest training and prediction. Accuracy, F1, Precision, Recall, confusion matrix, ROC/AUC calculation.page4_results.RAssembles final output — calls lexicon or ML file depending on selection. Builds all chart data objects. Generates insight text from computed values.app.R / server.RMain Shiny server and UI file. Imports all page R files. Handles navigation between pages and reactive state.Priority order for building: get each method producing correct output first (page4_lexicon.R and page4_ml.R), then connect the UI around it. Do not build the UI before the R analysis is verified working.End of specification.
